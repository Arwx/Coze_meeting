## 会议背景

系统需要存储用户、角色、配置、审计日志、业务记录和文件元数据。本次会议讨论关系型数据库、迁移工具、ORM 以及索引设计原则。

## 讨论内容

1. 数据库选择

   PostgreSQL 在 JSON 字段、全文检索、事务能力和扩展生态上表现稳定，适合当前业务。MySQL 也可用，但团队希望保留后续更复杂查询能力。

2. ORM 选择

   Prisma 类型体验好，迁移清晰，适合 TypeScript 项目。TypeORM 与 NestJS 集成成熟，但历史项目中遇到过实体装饰器和迁移维护成本问题。

3. 迁移管理

   所有表结构变更必须通过迁移文件提交，不允许直接手工改生产库结构。

4. 索引策略

   先为外键、唯一字段、时间排序字段建立基础索引。复杂组合索引需基于实际查询计划添加。

## 关键结论

- 主数据库采用 PostgreSQL。
- ORM 采用 Prisma。
- 所有 schema 变更必须生成 migration。
- 审计日志单独建表，避免和业务表强耦合。
- 本地开发使用 Docker Compose 启动数据库。
