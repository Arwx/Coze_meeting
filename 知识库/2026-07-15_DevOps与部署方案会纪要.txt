## 会议背景

项目需要从一开始建立稳定的构建、测试和部署流程。会议讨论 Docker、CI/CD、环境变量、日志和发布策略。

## 讨论内容

1. 容器化

   前端构建为静态资源，由 Nginx 提供服务。后端构建为 Node.js Docker 镜像。数据库和 Redis 通过托管服务或独立容器运行。

2. CI 流程

   每次提交触发 lint、typecheck 和测试。主分支合并后构建镜像并推送到镜像仓库。

3. 环境管理

   环境分为 local、dev、staging、prod。敏感配置通过环境变量注入，不进入代码仓库。

4. 发布策略

   一期采用滚动发布。发布前必须完成数据库迁移检查和回滚方案确认。

## 关键结论

- 使用 Docker 构建前后端镜像。
- CI/CD 使用 GitHub Actions 或企业内部流水线。
- 环境变量统一通过 `.env.example` 说明。
- 日志输出 JSON 格式，便于后续接入日志平台。
- 生产发布必须有回滚说明。
